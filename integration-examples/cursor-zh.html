通过 Hologrow 分析已同步记录，不修改出价、预算、商品或订单。执行前请复核 AI 结论。

07 / 常见问题

Cursor 集成常见问题

连接方式、实际工作流程，以及首次分析前需要核实的内容。

Hologrow 如何融入 Cursor 项目？

Cursor Agent 通过 MCP 读取已同步 Hologrow 数据，作为分析与实现背景。报表代码、计算规则和部署流程仍由你的项目管理。

Cursor 应配置 OAuth 还是 MCP key？

Hologrow Cursor 指南当前指定 MCP key、Streamable HTTP 和 Bearer 授权 header。使用指南中的安装提示词与 Cursor 原生 MCP 配置。

Cursor 可以依据我的实际数据生成报表吗？

授权后，可以读取当前 Hologrow 用户可访问的表。制作报表前，应先检查这些表与日期范围，不可用的来源应明确标为缺口。

生成的看板会由 Hologrow 自动托管吗？

不会。Hologrow 提供已同步数据层。看板框架、刷新流程、托管与访问规则属于你的应用项目。

可以把 MCP key 写进前端代码吗？

不要在公开浏览器代码、截图或共享文件中暴露 key。授权应保留在文档指定的客户端配置中，独立应用则需采用合适的服务端密钥管理。

为什么要检查 Schema，而不是让 Cursor 猜？

表粒度、字段名与业务定义会决定计算方式。猜测可能把商品行重复计为订单，或混淆广告归因收入与店铺销售。

MCP 只读是否也代表 Cursor 不能修改代码？

不是。Hologrow 的只读边界针对通过其工具访问的店铺与广告数据。Cursor 能否修改本地项目文件，由 Cursor 权限另行控制。

项目里能使用 Amazon 之外的数据吗？

可以。除 Amazon 来源外，还包括 Google Ads、GA4、Search Console 和 Shoplazza 等支持来源。合并记录前，应检查账户实际可用性并验证映射。
