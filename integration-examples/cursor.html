07 / QUESTIONS, ANSWERED

Cursor integration FAQ

Connection details, practical workflows and what to verify before your first analysis.

How does Hologrow fit into a Cursor project?

Cursor Agent uses MCP to read synchronized Hologrow data as context for analysis and implementation. Your repository still owns the report code, calculation rules and deployment process.

Do I configure Cursor with OAuth or an MCP key?

The Hologrow Cursor guide currently specifies an MCP key, Streamable HTTP and a Bearer authorization header. Use the guide’s installation prompt with Cursor’s native MCP configuration.

Can Cursor generate a report from my actual data?

After authorization it can read the tables available to your Hologrow user. Ask it to inspect those tables and date ranges before building the report; unavailable sources should remain explicit gaps.

Is the generated dashboard automatically hosted by Hologrow?

No. Hologrow provides the synchronized data layer. The dashboard’s framework, refresh process, hosting and access rules are part of your application project.

Can I put an MCP key in frontend code?

Do not expose the key in public browser code, screenshots or shared files. Keep authorization in the documented client configuration and use appropriate server-side secret handling for any separate application.

Why inspect schemas instead of letting Cursor guess?

Table grain, field names and business definitions determine the calculation. Guessing can turn item rows into duplicate orders or mix ad-attributed revenue with store sales.

Does read-only MCP prevent Cursor from editing my code?

No. Hologrow’s read-only boundary applies to store and advertising data through its tools. Cursor’s ability to edit local project files is controlled separately by your Cursor permissions.

Can I use more than Amazon data in the project?

Yes. Supported sources include Google Ads, GA4, Search Console and Shoplazza, alongside Amazon sources. Check actual account availability and validate mappings before combining records.
